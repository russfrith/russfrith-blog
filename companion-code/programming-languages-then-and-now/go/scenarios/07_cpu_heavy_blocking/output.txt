Confirms the prediction: the heartbeat goroutine keeps ticking on schedule (every
~100ms) WHILE the CPU-bound loop runs on the main goroutine, with no explicit
offloading needed -- Go's scheduler runs goroutines across real OS threads
(GOMAXPROCS of them) rather than cooperatively on one, so a CPU-bound goroutine does
not freeze everything else the way it does in Node or default-build Python asyncio.
Kotlin coroutines on Dispatchers.Default (a multi-threaded pool) and Rust async
tasks that avoid putting blocking work directly on an executor thread behave the
same way; neither was run as a separate full demo here (one line/row, per the
post's own rule about showing full detail only where something notable happens).
