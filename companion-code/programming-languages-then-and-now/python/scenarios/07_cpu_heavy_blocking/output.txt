Confirms the prediction exactly: 0 heartbeat ticks while the CPU-bound loop runs
directly on the event loop task with no await points; 12 ticks (consistent with
~1.3s / 100ms) once the same work moves to run_in_executor's thread pool. Note this
improvement comes from asyncio being able to schedule around a blocking call
running on another OS thread, not from true CPU parallelism -- the executor thread
still contends for the GIL with the event loop thread in this build.
