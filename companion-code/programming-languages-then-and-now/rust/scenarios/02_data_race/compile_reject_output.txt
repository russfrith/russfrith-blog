Confirms the prediction exactly for both: a plain captured mutable counter fails
the borrow checker (E0373/E0499/E0502, before even reaching a Send/Sync question),
and an Rc<RefCell<i64>> fails the Send trait bound (E0277) because Rc is
deliberately not thread-safe (non-atomic refcounting). Neither failure is a
runtime race -- both are compile-time rejections, so the broken program never
runs at all. This is why the existing `unsafe`/`static mut` version
(broken.rs/output.txt in this same folder) is necessary to show an actual Rust
data race: safe Rust has no legal way to write the naive mistake.

Precise claim for the post: safe Rust prevents DATA RACES (concurrent unsynchronized
access to shared mutable memory) at compile time. It does NOT prevent all race
CONDITIONS (e.g. two threads racing to acquire a lock and get different,
order-dependent results is still possible and compiles fine) or deadlocks (two
threads each waiting on a lock the other holds also compiles and runs, and can
hang forever) -- those are logic errors the type system doesn't catch.
